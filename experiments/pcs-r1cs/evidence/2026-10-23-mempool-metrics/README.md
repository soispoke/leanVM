# Mempool metric contract and standalone verification

New reports use time to mempool-ready proof (witness plus the one wallet proof and encoding), mempool proof bytes, native verification in a separate process and peak client RAM. The legacy second client proof is the wrap proof. Merge reports name merge time and merged-proof bytes, retaining input heights so node-plus-leaf observations cannot be mistaken for two-node merges. Combined-process RAM and self-verification are explicitly diagnostic. The reporting changes do not change prover/verifier equations, transcript data, circuit shapes or proof bytes.

`CLOSED.md` gives the exact native entry point, transport decoding and height/statement checks, and the trusted base setup/key binding. The mempool role now requires `--input`, `--statement` and `--base-key`; the named application selects trusted setup independently. Standalone verification accepts a fresh BLAKE64 base certificate and rejects both an incorrect external statement and an incorrect pinned key. No wrap or recursive merge is created by this verification process. Ethereum-client format compatibility is not established.

All final gates pass on identical unchanged sources, CPUs 0-11, with `CARGO_BUILD_JOBS=12`, `LEANVM_NUM_THREADS=12` and `RAYON_NUM_THREADS=12`: formatting, all-target release Clippy with `-D warnings`, 79 format_recursion tests, 43 rec_aggregation tests (five ignored), doc tests, the native-adder example regression and the profiler build. Fresh base and first-merge certificates verify and match the exact historical bytes, with lengths 247,956 and 361,196. These are interface/compatibility checks, not a new performance comparison or matrix rerun.

The two format-edit receipts ran the formatter successfully but deliberately changed sources, so their wrapper results are unsuccessful and are not gates. The wrong-statement and wrong-key receipts intentionally exit unsuccessfully; their rejection is the expected result, as recorded in `standalone-checks.json`. Only later unchanged-source receipts are frozen gate evidence. Raw results and compressed logs are archived with stored-file hashes.

`schema-migration.json` records the canonical rename of 138 lane A rows in the shared matched-results export. It preserves numeric observations, performs only exact bytes-to-KiB RAM conversion, and retains the old metric name. Other lanes' rows remain byte-for-byte unchanged. The six old node-plus-leaf timing records become `merge2to1_unequal_height_s`, retaining input heights, so the live table no longer presents them as two merged proofs. Historical raw receipts and archived reference records remain unchanged. The live table was regenerated through its existing reader; no other lane's source or measurement was edited. It includes concurrent lane results, whereas the frozen native reference is explicitly tied to its measured commit.

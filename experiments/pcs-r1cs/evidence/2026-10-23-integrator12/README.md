# Lane A integration and superseding resource policy

Lane A uses CPUs 0-11 for every command, with `CARGO_BUILD_JOBS=12`, `LEANVM_NUM_THREADS=12` and `RAYON_NUM_THREADS=12`. The frozen runner and plan are preserved here. This policy supersedes the prior 16-thread split benchmark/build policy in `2026-10-23-resource-policy`; that historical evidence retains its actual settings. The original quick application matrix was unpinned and is unmatched to the new reference. Existing completed receipts were read, never rerun.

Six lane C commits through `73dc61d7` add opt-in compiler-policy research, census/reporting and stronger rejection tests. The default compiler policy and prover/verifier graphs remain unchanged. No new trimming default, rate change or capacity claim is accepted here. C's measurements on CPUs 24-35 retain their lane attribution. The role profiler adds actual CPU/thread metadata, separately timed encoding and a mempool process that decodes and verifies the saved native certificate against its independently reconstructed application claim and trusted base key.

All final gates ran on the same frozen source hashes and report unchanged files: format check, release all-target Clippy for format_recursion and rec_aggregation with `-D warnings`, release tests (79 format_recursion; 43 rec_aggregation, 5 ignored; doc tests), the strengthened native-adder example regression, and the role profiler build. The resource assertion confirms the inherited CPU mask and all three thread/job knobs. Fresh BLAKE64 base and first-merge certificates verify and match the exact saved certificate bytes, including their 247,956-byte and 361,196-byte lengths. This is a compatibility check, not a timing comparison.

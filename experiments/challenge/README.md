# Trial referee harness

Deadline and entry interface are in `P/artifacts/trial/state.json` and `ENTRY-FORMAT.md`. No push is authorized.

`harness.py run --out <new-sample-dir> --forwarded <path> -- <argv...>` pins the command to cores 36-47 with both thread counts 12. It records complete process lifetime, stdout, stderr, binary hash, exit status, all forwarded file bytes and simultaneous process-group RSS. Cgroup v2 is mounted read-only here (mkdir was tested and refused). The fallback sums RSS every nominal 5 ms and records actual sample gaps, shared-page overcount and escaped/short-lived-child limitations. It is not exact cgroup memory.peak. A two-process allocation probe is retained in `runner-integrity-smoke/`.

`freeze <manifest> <new-dir>` snapshots aggregate-key bytes and hashes binaries. `draw <freeze-dir> <out>` checks that all frozen files still match, then records a fresh random seed and selects two applications. No draw is allowed with a missing aggregate-key file.

`inputgen/` creates actual seeded relation inputs. A is the shared depth-20 Keccak shielded spend. B generates a fresh PQClean Falcon-512 key and signature using tide-fn-dsa 0.4, independently decodes and verifies them, and emits the reduced decoded-coefficient relation plus the original encodings. This does not make the reduced relation a parser proof. MPT uses the existing synthetic circuit instance; it is not silently equated to leanVM's mainnet fixture. Merkle uses the corrected shared path convention. All fresh input generation is separate from key freeze and held-out selection.

`trial_wallet.rs` is a referee adapter over the baseline row bridge. It retains the baseline protocol, compiles/setup using a public seed-zero fixture before reading supplied instance files, and supports cold and persistent warm requests. The outer process timer includes setup; its labelled wallet timer includes instance decoding, witness creation, proving, encoding and file write. Setup cannot yet export an independently reloadable key, so cold timing is a conservative combined-process observation rather than the exact retained-key-only boundary.

`build_scoreboard.py` derives the current cost vector and conservative gate observations from raw receipt summaries. `score.py` accepts no scalar unless every scored component has at least ten distinct raw receipts across five rounds, explicit scored/fresh/complete labels, independent children for merges, matching external medians, and forwarded files whose sizes and hashes still match. Gate prerequisites involving security, arbitrary-generator admission and reference upgrades still require a referee audit; this is not an untrusted-host attestation system. Existing control labels deliberately do not satisfy scored-component scope.

`wallet_qualified.py`, `complete_merges.py` and `admission_suite.py` are the complete-envelope baseline runs. `certificate_rejections.py` and `merge_rejections.py` mutate already-created certificates at verifier targets. `entrant_suite.py` measures entry 2's local composition controls; `heldout_entry4.py --entry entry-4` (or `entry-5`, `entry-7`, `entry-8`) measures separately frozen Keccak entries. `root_series.py` runs the local one/two/three-application root sweep. `exact_suite.py` tests shared fresh Falcon/MPT statement inputs with L7's published exact guests; its BLAKE2s guest is a software-Keccak control and its Keccak guest uses the native instruction. `cold_merges.py` includes fresh process, setup and child preparation, an upper-bound cold control rather than retained-key-only cold.

`external_entry6.py` exercises one novel post-freeze canonical graph and malformed public descriptions. `receipt_inventory.py` counts successful and failed process requests without equating failure with verifier rejection. `final_receipt_audit.py` checks retained forwarded-file sizes/hashes and deadline receipts. `render_report.py` generates the live report, or the final report with `--final`. These integrity checks do not certify soundness.

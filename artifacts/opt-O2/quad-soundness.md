# Quaternary WHIR authentication

The optional `keccak-merkle-arity4` configuration changes actual PCS commitments, pruned octopus transport/expansion, raw authentication paths and recursive verification together. Every two binary levels become one four-child node; an odd binary depth retains a final two-child root. Four 32-byte children occupy 128 bytes and take one standard Keccak-256 permutation at rate 136 and capacity 512. The existing flat binary allocation is retained, including unused intermediate levels; concurrent completion geometry is unchanged and redundant intermediate hashes are still computed natively. This prototype optimizes recursive permutation count, not native tree-builder memory.

Leaf images and packing, position counts, query counts, OOD schedule, code rates (including leaf rate 1/4) and grinding bits are unchanged. The observed L0 leaves hold 64 F64 words (512 bytes, four permutations); later leaves hold 48 words (384 bytes, three permutations). Application statements and their application-level Merkle trees are unchanged; only WHIR commitment trees change. The sparse setup key includes an explicit arity version domain, preventing those keys from being silently reused across protocol shapes.

Security accounting assumption: the same WHIR proximity/query argument applies because sampled leaf positions and opened lane values are unchanged. Authentication binding is reduced to a collision in the same 256-bit Keccak digest; generic collision security remains 128 bits, with no change to Keccak capacity or rate. This relies on the original random-oracle/collision-resistance assumptions, not a new formal proof. Paths now carry three siblings per quaternary step, so bytes can grow even when permutations fall. Proof-size and admission limits must be checked from measurements.

The native suites compare concurrent tree construction with a sequential reference over varied sizes, padded rows and block splits, and reject missing/repeated blocks and malformed openings. The recursive raw-path regression spans depths 1–6 (including odd roots and duplicate positions), mutates every sibling position, and rejects wrong leaves, query challenges and leaf widths. Full recursive package tests and mixed-tree verifier probes cover false carried claims, wrong identities/kinds, reordered children and tampered proofs. Tests are implementation regression evidence and do not establish formal soundness or general node-key closure.

## Shared quaternary cap

`keccak-quad-cap` shares upper authentication nodes without changing the native proof or commitment. A fixed upper height, derived solely from public depth and query count, is chosen so the remaining lower path comprises full quaternary levels. Every supplied upper sibling is equated to its selected cap node, including siblings for regions also reconstructed by another query. Query bits constrain Boolean occupancy products; occupied parents must equal the hash of their children, while unoccupied regions stay opaque. The top cap node is constrained to the original commitment. Sparse and distributed occupancies record the same program. This relies on the authentication binding argument above and does not change proximity parameters.

The optional `keccak-quad-cap-fast` feature computes the same occupancy indicators with a shared multilinear kernel. It also omits range decomposition of supplied sibling aliases only when a full F192 equality binds them to already canonical selected digests. The regression mutates the discarded high limb directly in a raw trace input and requires rejection, in addition to all sibling mutations. This is not a truncating equality.

The 21/21 first/node example wrappers are validated only for the measured mixed depth-two statement. Active dimension mismatches reject. General repeated node-on-node closure and sustained one-arrival-per-second throughput are not established by these measurements.

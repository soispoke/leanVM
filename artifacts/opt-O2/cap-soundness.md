# Shared upper Merkle levels in the recursive verifier

Feature: `format_recursion/keccak-merkle-cap`. Native commitments, proof transport, WHIR rates/query counts, grinding and Fiat–Shamir challenges are unchanged. Each phase retains its exact leaves and tree positions. The circuit shares the upper four levels of the binary tree. It computes a Boolean occupancy predicate for each cap region from every transcript query and derives ancestor occupancy by OR. An occupied internal node must hash its two children; an unoccupied node may use a supplied opaque digest. Every queried leaf authenticates to its selected cap node. Every supplied upper sibling is also equated to its selected shared node. The shared root equals the original commitment root. Thus no supplied sibling or queried leaf is silently omitted. Opaque subtrees carry no queried opening and have the same role as ordinary Merkle siblings.

This is an adaptation of Merkle caps/multiproofs, e.g. [Plonky2 MerkleCap](https://docs.rs/plonky2/latest/plonky2/hash/merkle_tree/struct.MerkleCap.html). It does not change the committed tree arity, leaf image, Keccak rate 136/capacity 512, or original 128-bit WHIR security accounting. Its circuit shape depends only on fixed depth and query count; duplicate and distributed queries use the same program. Host reconstruction chooses witness values only; circuit equations authenticate those values.

The feature also infers F64 membership from key-pinned F64 constants, Boolean constraints and enforced equations a*b+c=d, using closure under addition/product and inverse addition when the multiplier is the pinned one. It never infers from private values or divides by an unproven nonzero witness. Remaining limbs retain native Keccak range checks.

Rejection regression `cap_binds_every_sibling_and_query_in_fixed_shape` uses raw paths (bypassing compressed native opening checks), tests sparse duplicates and distributed positions, mutates every sibling of every query at every level, changes a leaf and changes a query challenge. Existing package tests and the mixed-tree example cover omitted zero packing, false carried claims, substituted application keys, reordered children and tampered proof streams. Passing tests are regression evidence, not a formal soundness proof.

The first cap prototype omitted redundant sibling equalities and failed its rejection test. It was rejected; the current implementation restores those equalities. No native transport-format change is claimed. The feature is experimental and opt-in; default Keccak lowering retains its original typing calls.

# Shielded small-table lookup relation (research prototype)

The opt-in lowering uses three fixed domains. RANGE8 has 256 rows and one coordinate `x` for `0 <= x < 256`. NIBBLE_LOGIC has 256 rows indexed by `(a,b)` with four columns `(a,b,a xor b,a and b)` where `a,b` are 4-bit values. NIBBLE_ADD has 512 rows indexed by `(a,b,carry)` with five columns `(a,b,carry,sum,carry_out)` for 4-bit `a,b`, one-bit carry, and `a+b+carry = sum + 16*carry_out`.

Each byte range check is one RANGE8 read; each former RANGE16 value limb is two RANGE8 reads. The current spend emits no NIBBLE_LOGIC reads: equality/zero remain arithmetic field tests, and swaps remain arithmetic gates. NIBBLE_LOGIC is fixed in the index but currently unused. Byte addition is lowered to two NIBBLE_ADD reads, propagating carry from the low nibble to the high nibble. The spend has 3,704 lookup reads in this mode (3,568 RANGE8 and 136 NIBBLE_ADD; logic reads are represented by the range path for the current equality/zero lowering).

The table columns are canonical, public index data. They are generated once during `LookupBridge::new`, hashed into `table_digest`, and included in the setup/index transcript label. They are not copied into the per-proof witness or committed per proof. Per proof data consists of query coordinates and a bit multiplicity vector over the concatenated 256+256+512 rows. The table tag and zero-extended tuple coordinates are copied into aligned native witness rows.

One batched product-bus/GKR reduction proves that the multiplicity-weighted fixed-table fingerprint equals the query fingerprint. Multiplicity bits are checked for Booleanity with the zerocheck component; duplicate reads increment the same count. The table digest, shape, table log, query log, query layout, public digest, and context are all transcript-bound. The base verifier checks the native arithmetic, hash rows, table-bus claims, PCS openings, and public digest. This is a research prototype; the verifier path and transcript binding need the normal integration audit before production use.

The strict end-to-end adversarial test constructs proofs while bypassing host validity checks and requires base-verifier rejection for out-of-range query coordinates (256 in RANGE8), wrong table tag, swapped query rows, invalid value conservation, and altered multiplicity counts. The swapped-row case preserves the complete query multiset and counts, so it tests binding to the native committed copy rows. Only the prover test harness bypasses its query consistency check, using a cfg(test) thread-local flag; the base verifier is unchanged. Evidence: ht-L3-strict-rejections.log (passed).

Three alternating rounds at 12 threads, CPUs 24-35: small 96.696/87.508/101.020 ms, native hash-rows-only 271.355/240.956/284.445 ms. Means 95.074 ms and 265.586 ms. Small verification in separate processes: 5.819/5.949/5.882 ms; native: 8.549/5.310/5.257 ms. Small has 17,202 core arithmetic rows, 44,992 after query binding, 65,536 padded rows; 884,736 committed words and 250,280 proof bytes. Both match the reference digest for leanvm_input(0), with 106 compressions and the same spend rules. Setup is excluded. This measurement includes the extra final hash used for the VM public digest.

Integration is research and opt-in (`LOOKUP_SMALL=1`), not the default. SHA256/Keccak lowering is not included in this result.

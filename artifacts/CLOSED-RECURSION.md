# Experimental common-key recursive relation

This document specifies the recursion layer implemented by `format_recursion::closed_recursion`. It is a tested construction conditional on the native arithmetic, Flock, bridge, WHIR and Fiat-Shamir assumptions. It is not a formal proof of their composition or an official recursion.fast submission.

Fix a BLAKE2s chain length and the context `format-closed-recursion-v1`. Let H be BLAKE2s-256. A leaf starting at a private 32-byte value x applies `x := H(0x43 || x)` for the fixed chain length, then publishes `H(0x4c || x || LE64(chain_length))`. An internal node publishes `H(0x4e || left_statement || right_statement)`. Children are ordered. The root commits to these leaf statements and their tree structure; it does not expose their starts or certify a shielded-transfer workload.

One fixed circuit has a private Boolean mode and public values `[key_lo128, key_hi128, height_u32, statement_lo128, statement_hi128]`. Hash halves follow the backend's little-endian scalar encoding. Leaf mode enforces height zero and the leaf statement. Node mode enforces both child verifiers, with the same public key, fixed metadata, context and fixed constants; it enforces `height = 1 + max(left_height, right_height)` with range-constrained 32-bit integers and no overflow, and binds the ordered node statement. All arithmetic operations and all hash I/O are constrained in both modes. Only the child verifier acceptance equations are multiplied by the Boolean mode. Dummy verifier inputs in leaf mode are not valid child proofs and need not satisfy those acceptance equations.

The trusted setup derives the verifier's metadata and constant vector by exact iteration before constructing commitments. Public capacity and hash-block capacity are padded canonically. It accepts only a stable metadata and constant vector, a satisfied canonical leaf witness and an actual setup shape equal to the derived shape. This is metadata self-description, not a hash fixed point. The key is a public circuit input; the external verifier always pins it to the actual setup key. Callers cannot authorize a replacement key by changing a certificate.

A certificate consists of a 32-bit height, a 32-byte statement and a backend proof. Its wire format is fixed-integer bincode, bounded by the backend proof cap plus 36 bytes. Decoding rejects trailing, truncated and oversized data. Decoding alone does not verify a proof. `ClosedSetup::verify` supplies the pinned key, canonical fixed public prefix and context. `prove_node` also checks its child certificates before recording them; the circuit still checks both child verifier relations.

Conditional recursive argument: assume the backend provides knowledge soundness for the fixed circuit and the transcript/hash assumptions hold for nested invocations. Extract an accepted circuit witness under the externally pinned key. Its Boolean mode yields either the base relation at height zero or two accepted child verifier relations at strictly smaller nonnegative heights. Induction on the bounded height terminates and gives the stated leaf/node semantics for a finite tree, including mixed-height children. An efficient recursive extractor, concrete security loss, and a formal proof of the native PCS/Flock composition remain open. Unit tests establish functionality and rejection cases, not this knowledge-soundness theorem.

Performance comparisons must record the whole workload, setup, proof creation (recording, child prechecks, witness preparation and proving), verification, shape and per-certificate sizes. Closure changes the old finite-tree circuit. Only optimization experiments against a frozen common-key construction can claim invariant shapes and proof sizes.

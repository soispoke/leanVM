# Entrant feedback (red team, never a scored entry)

1. **ambiguous — conflicting application bounds.** Fixed setting allows two real applications; workloads require held-outs merged with A and B and root gate requests three. A four-slot implementation can cite the former to evade the latter. Fix: require at least three real identities plus all wrapper identities simultaneously, with explicit maximum dimensions, depth and claim count.
2. **gameable — per-identity averaging.** Dividing total root time by identity count can hide a 14 ms wrapper behind cheap applications. Historical evidence demonstrates this. Fix: report each settlement and total complete acceptance; specify whether the 10 ms limit is on isolated settlement or allocated complete acceptance. Count wrappers.
3. **ambiguous — historical evidence and provisional hashes.** Trial status allows BLAKE2s measurements but fixed setting mandates Keccak everywhere; clarify eligibility versus provisional reporting and whether a score exists before hash parity. Never mix a BLAKE merge with a Keccak wallet into an unlabelled score.
4. **gameable — deterministic fixtures/setup leakage.** Setup can precompute witness-dependent values if seeded fixtures are predictable, or retain hidden process memory. Fix: coordinator reveals random seeds after artifact freeze; audit retained artifacts and run setup without witness access.
5. **gameable — reduced Falcon.** A decoded-coefficient relation avoids compressed-byte parser constraints and can be presented as full verification. Fix: separate reduced and full score tracks and require raw encoded input rejection vectors.
6. **ambiguous — held-out shape admission.** Frozen identities alone do not guarantee frozen generator bounds or layouts. Fix: coordinator freezes shape bounds before revealing at least two generators; authenticate canonical generator bytes and deterministic keys, then demonstrate three-real-app node merges without regenerating aggregate setup.

These are documented attacks on interpretation; none is represented as implementation progress or an eligible entry.

7. **ambiguous — CPU assignment conflict.** ENTRY-FORMAT specifies cores 36–47 while entrant authorization assigns 0–11; both use 12 threads. Entrant follows explicit 0–11 restriction. Fix: record lane-specific affinities in runner configuration and referee remeasure on common reserved cores.

8. **gameable — characteristic-two one-hot routing.** Checking Boolean route selectors with only sum=1 permits three selected routes because 1+1+1=1. Fix: prefix exclusivity plus total-one, and bind selectors before the folding challenge. The prototype uses both checks; no attack entry submitted.
9. **gameable — tiny key digest versus retained setup.** Reporting only aggregate.key (32 bytes) hides the 213 MiB public cache, 126 MiB matrix setup and 28 MiB generator trace in the prototype. Fix: sum all retained artifacts and include runtime caches, plans and canonical generators; distinguish duplicated diagnostics from required runtime state explicitly.
10. **ambiguous — one aggregate identity at multiple points.** A node carrying a prior aggregate claim also leaves its own fresh aggregate claim at another point. Single-key recursion therefore can require two evaluations of the same matrix identity at the root. Fix: define whether 10 ms applies to all work for an identity, every evaluation, or total/identity; require all fresh and inherited evaluations and count them separately in the schema. Do not count the aggregate identity twice to inflate the denominator.
11. **ambiguous — setup only reads generator bytes versus compilation witness.** Existing trace compilers use a dummy proof to record a value-independent verifier graph. This is public dummy data, but literally reads more than generator bytes. Fix: permit deterministic public test vectors generated from a fixed public recipe, forbid real/private input access and require witness-erased retained generator bytes.
12. **gameable — security parameter ambiguity.** Unchanged historical query/grinding knobs do not certify 128-bit composition for a new depth or number of deferred claims. Fix: coordinator publishes the exact calculator and binding configuration; reject unsupported budgets rather than accepting unchanged constants as evidence.
13. **ambiguous — all Keccak calls versus SHAKE padding.** Fixed setting says Keccak-256 Ethereum padding for every hash, while Falcon mandates SHAKE256. Fix: explicitly permit SHAKE suffix/rate for Falcon while requiring Keccak-256 for protocol hashing; both use Keccak-f[1600].
14. **gameable — generator versus key identity.** Current carried keys hash lowered matrices with BLAKE2s while application IDs must hash canonical generator bytes with Keccak. Substituting a key digest for application ID can hide generator changes. Fix: freeze canonical generator grammar and bytes; authenticate deterministic key derivation and include the canonical application ID in the statement commitment or prove the equivalence precisely.
15. **unworkable — unspecified upgrade backend.** The independent binary-only upgrade backend and acceptance interface are not supplied. No entrant can independently establish the 1-hour/64-GiB gate from the rule page alone. Fix: publish a versioned binary, generator format, cross-version vectors and measured supported bounds before declaring eligibility.
16. **gameable — complete forwarded bytes.** Example timers serialize only the outer proof, omitting statement slots, claims, key authentication and dependency sidecars. Fix: verifier must accept from one forwarded directory plus frozen public setup; count every regular file and prohibit hidden original-process state.
17. **gameable — admission checks may defer rejection.** A cheap parser or outer-only verifier can claim <20 ms by postponing identity authentication and false carried claims until root. Fix: define the incoming-proof acceptance predicate and deferred obligations explicitly; report decoding, authentication and each proof check separately.
18. **ambiguous — throughput and latency under 1,000 ms arrivals.** Repeated isolated node runs do not measure queueing when service time exceeds interval or jobs overlap memory. Fix: specify open-loop arrivals, concurrency, duration, warm state, backpressure and end-to-end p95 including queue time.
19. **ambiguous — protocol techniques versus security changes.** Permission to change sumcheck/GKR/hash reduction can silently change the composed security model. Fix: require equation/transcript diff, citation and calculator receipt, not a technique name alone.
20. **too strict — one fixed rate at leaves across very different layouts.** The wallet cap already fails decoded Falcon by over an order of magnitude; tightening a relation without a calibrated reference can make the full-relation track empty. Fix: preserve the failed deployment gate but publish separate calibration vectors and reduced/full performance, never relax it covertly for an entry.
21. **gameable — fresh seed with repeated actual witness.** Printing a new seed or changing unused bytes satisfies a superficial freshness check while reusing the same circuit witness. Fix: coordinator checks the instance transcript and consumes independent seeded inputs per child; require a source generator digest independent of the seed.
22. **ambiguous — ZK surface accounting.** No-ZK timing may be compared against a privacy-ready baseline despite the status text. Fix: mark ZK=false on every sample and keep privacy-ready claims on a separate measured pass.
23. **gameable — frozen tables without decoder accounting.** A tiny table manifest can invoke a large procedural decoder or application-specific specialization hidden in lowering. Fix: freeze decoder, contents, columns, transcript rules and query materialization; count source/binary/spec dimensions and reject post-draw special cases.
24. **ambiguous — sort/dedup versus ordered digest.** Block-level dedup can remove repeated dependencies while the proof digest is order sensitive. Fix: state exact leaf multiplicity/order semantics and bind that list before any block-level normalization. Include repeated-app independent witnesses in rejection/coverage tests.
25. **gameable — strict proof transcript versus permissive file decoder.** A verifier may consume its whole internal proof vector while bincode silently accepts bytes after the serialized certificate or sidecar. Fix: require canonical transport decoding with trailing-byte rejection, and test appended bytes on every forwarded component. The follow-on adapter now uses fixed-int bincode with explicit reject_trailing_bytes; earlier frozen binaries are not retroactively credited with the fix.
26. **ambiguous — public evaluation plans versus stored circuit matrices.** A generator can analytically sum structured constant-padding entries and retain a public evaluation plan, changing root costs without changing the circuit. Fix: permit exact algebraic compilation explicitly, count retained public plans/RAM, and cross-check matrix evaluations against the canonical matrix on independent points. Keep cold loading and warm plan preparation separate.
27. **gameable — declared depth is not necessarily authenticated.** A reusable aggregate state with only a wallet/node Boolean can accept more recursion levels than a manifest's tested depth2, even when slot count is bounded. This makes a depth/claim-count security budget unenforceable from the root certificate alone. Fix: authenticate height and covered-leaf/merge counts in the public state and ordered digest, enforce declared maxima inside every merge, and include over-budget rejection cases. Entrant prototypes report depth2 as tested scope, not an enforced global depth limit; no certified composition budget is claimed.
